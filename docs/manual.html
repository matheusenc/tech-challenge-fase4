01 · Visão do projeto

O sistema analisa gravações clínicas simuladas e dados de monitoramento para identificar padrões potencialmente anômalos e gerar informações de apoio à revisão humana.

VídeoPostura e possível queda em fisioterapia; objetos em área definida de uma simulação de cirurgia.
ÁudioTranscrição, características da voz, termos críticos e análise de sentimento.
Dados clínicosSinais vitais, registros de prescrição/administração e níveis de movimentação.
Uso acadêmico. Regras e limites são ilustrativos, não validados clinicamente. Resultados não constituem diagnóstico nem devem orientar decisões médicas autônomas.

02 · Arquitetura e fluxo multimodal

O arquivo main.py organiza a execução sequencial das análises. Cada módulo devolve alertas padronizados. O módulo de alertas ordena os eventos e calcula a prioridade por paciente; o relatório reúne os resultados.

Importante: a consolidação atual agrupa eventos pelo identificador do paciente. Correlação por janelas temporais, persistência em banco, painel web e streaming multimodal contínuo são propostas de evolução, não funcionalidades demonstradas como concluídas.

04 · Módulos e modelos

Vídeo — monitoramento/analise_video.py

Para fisioterapia, o YOLOv8-Pose estima pontos do corpo, utilizados para medir inclinação do tronco e deslocamento do quadril. Para a simulação de cirurgia, o YOLOv8 detecta classes gerais de objetos e verifica sua presença em uma região crítica configurada.

A presença de uma tesoura em cena não significa, por si só, erro cirúrgico. O cenário deve ser apresentado como simulação controlada.

Áudio — monitoramento/analise_audio.py

librosa calcula indicadores como pausas e ritmo de fala. O Azure Speech oferece transcrição e diarização quando configurado; o Azure AI Language analisa sentimento e frases-chave. Sem Azure Speech, pode haver uso de transcrição local .txt, o que não comprova integração em nuvem.

A identificação do falante e o contexto de negações devem ser verificados para evitar que uma pergunta do médico seja atribuída como sintoma do paciente.

Sinais vitais — anomalias_sinais_vitais.py

Regras de limiar, variação baseada em histórico e Isolation Forest avaliam frequência cardíaca, pressão arterial e oxigenação. Os limites são ilustrativos.

Prescrições — anomalias_prescricoes.py

Regras verificam doses acima de limites definidos, aumentos bruscos, intervalos menores que o esperado e introdução de medicamentos selecionados. Dados de unidade, indicação e natureza do evento clínico precisam ser interpretados corretamente.

Movimentação — anomalias_movimentacao.py

Regras identificam inatividade prolongada, agitação noturna e queda da média diária de atividade.

Consolidação — monitoramento/alertas.py

Padroniza alertas, remove repetições em determinados fluxos, ordena por gravidade e agrupa por paciente. No projeto atual, a pontuação utiliza pesos ilustrativos para gravidade e quantidade de fontes.

05 · Instalação e configuração

  1. Abra a pasta do projeto no VSCode. Trabalhe na branch de desenvolvimento para preservar a versão principal.
  2. Crie e ative o ambiente virtual.
    python -m venv .venv
.\.venv\Scripts\Activate.ps1
  3. Instale as dependências.
    python -m pip install -r requirements.txt
  4. Configure o Azure quando for demonstrar a integração real. Copie .env.exemplo para .env e preencha apenas as credenciais necessárias. O arquivo .env deve permanecer fora do Git.
  5. Valide o ambiente com os testes.
    python -m pytest testes/ -q

06 · Execução passo a passo

Todos os comandos devem ser executados na raiz do repositório. Os arquivos de vídeo e áudio abaixo não vêm necessariamente incluídos; prepare gravações simuladas antes de utilizá-los.

1. Gerar dados de exemplo

python gerar_dados_exemplo.py

2. Executar a análise dos dados disponíveis

python main.py --sem-webhook

O programa ignora etapas cujos arquivos não existirem. Portanto, confirme no terminal quais análises realmente foram executadas.

3. Vídeo de fisioterapia

python main.py --video dados/fisioterapia.mp4 --tipo-video fisioterapia --paciente P001 --sem-webhook

4. Vídeo de cirurgia simulada

python main.py --video dados/cirurgia.mp4 --tipo-video cirurgia --paciente P001 --sem-webhook

5. Consulta simulada

python main.py --audio dados/consulta.wav --paciente P001 --sem-webhook

Se houver múltiplos falantes e a seleção automática não for confiável, informe o ID do falante do paciente com --falante-paciente.

6. Simulação sequencial de sinais vitais

python simular_tempo_real.py --paciente P001 --intervalo 0.1

Esta rotina simula chegadas de leituras de sinais vitais. Não equivale a streaming multimodal de áudio e vídeo.

07 · Alertas, relatórios e notificações

saida/alertas.jsonAlertas gerados no processamento principal, incluindo paciente, origem, tipo, gravidade e descrição.
saida/relatorio_monitoramento.mdRelatório automático com agregação de alertas e, quando executadas, análises de áudio e vídeo.
saida/alertas_tempo_real.jsonAlertas registrados pela simulação de leituras sequenciais.

Fluxo de notificação

Depois da análise, o sistema imprime os alertas no terminal e salva os dados em JSON. O envio por webhook é opcional e depende de configuração explícita na branch de melhorias. Para demonstrar o recebimento, use apenas informações sintéticas e um destino de teste controlado.

Importante: a soma de pesos entre modalidades não representa uma probabilidade clínica validada. O cálculo atual é uma heurística de priorização.

08 · Validação e evidências para a entrega

O enunciado exige relatório técnico com fluxo, modelos e resultados; e vídeo demonstrativo de até 15 minutos, publicado no YouTube ou Vimeo.

Antes de gravar

  • Executar pytest e registrar o resultado
  • Separar gravações autorizadas e simuladas
  • Confirmar que áudio e vídeo foram processados
  • Testar chamadas reais ao Azure
  • Preparar casos de anomalia e caso normal
  • Proteger chaves e identificadores sensíveis

Na apresentação

  • Mostrar arquitetura e dados de entrada
  • Demonstrar análise de vídeo
  • Demonstrar análise de áudio e Azure
  • Demonstrar anomalias clínicas
  • Mostrar alertas e recebimento no destino de teste
  • Mostrar relatório e limitações

Não invente indicadores: métricas de acurácia, recall, latência e quantidade de eventos devem vir de experimentos realmente executados. Documente ambiente, entrada utilizada e saída observada.

09 · Limitações, privacidade e próximas melhorias

Para demonstrar o projeto, prefira dados inteiramente sintéticos. Não publique dados de pacientes, gravações não autorizadas nem chaves Azure. A solução não substitui avaliação de profissionais habilitados.
